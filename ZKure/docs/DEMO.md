# Demo Walkthrough

Use synthetic data and a clean local database.

1. Start the API and Vite frontend with `npm run dev`.
2. Bootstrap a local administrator using environment variables.
3. Create linked demo accounts for Patient, Hospital, and Insurer roles.
4. Sign in as the patient and inspect the record vault and permission controls.
5. Demonstrate an application-level permission grant and revocation.
6. Sign in as the hospital and show the claim preparation workflow and current integration guardrails.
7. Sign in as the insurer and show the verification area, clearly identifying any unavailable proof/settlement integration.
8. Explain what a future proof would prove, what remains private, and what it cannot establish.

Do not present UI status, sample rows, local simulation, or a disabled control as proof generation or testnet settlement. A genuine ZK proof and chain receipt can only be demonstrated after those integrations exist and have been independently verified.
