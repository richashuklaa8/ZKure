# Contributing to ZKure

Thanks for your interest in improving ZKure.

## Before contributing

- Read the README, architecture and threat-model documents.
- Use synthetic data only. Never commit patient data, credentials, private keys or seed phrases.
- Check existing issues before starting substantial work.
- Discuss major architecture or cryptography changes before implementing them.

## Development expectations

- Keep changes focused and explain the reason for each change.
- Add or update tests for behavior changes.
- Document security assumptions and limitations.
- Do not describe simulated behavior as production functionality.
- Preserve third-party license notices.
- Never commit `.env` files or secrets.

## Pull requests

Include:
1. What changed and why.
2. How it was tested, with actual commands and results.
3. Security, privacy or compatibility implications.
4. Screenshots for user-interface changes where useful.

By submitting a contribution, you confirm that you have the right to submit it under the repository license.
